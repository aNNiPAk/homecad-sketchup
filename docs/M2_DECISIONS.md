# M2 Primitive Geometry Decisions

## Implementation plan

1. Add UUID metadata, a mutation guard, and one shared result envelope.
2. Add managed, bounded primitive creation using central mm/degrees validation.
3. Add resolver-based extrusion, follow-me, transforms, and conservative solid booleans.
4. Expose tools through MCP with annotations and capability checks; add Ruby, Python, and cross-language tests.
5. Add disposable-model smoke instructions, update docs/CI, run tests and package the RBZ.

## Contract choices

- All M2 points are world-coordinate `[x_mm, y_mm, z_mm]`. Angles are degrees. Conversion to/from SketchUp units stays in `HomeCAD::Units`.
- Every create tool creates a root Group container and stores geometry inside it, including a single edge or face.
- HomeCAD identity is an RFC 4122 UUID generated by Ruby's `SecureRandom.uuid`, stored with type, schema version, revision, and generated flag in the `HomeCAD` attribute dictionary. Inspection continues to avoid writing metadata.
- Every mutation is wrapped in one `HomeCAD::Operation`; errors abort. Shared target resolution and mutation policy reject missing/ambiguous, invalid, locked, nested-root, and generated non-primitive targets as applicable.
- `push_pull` and `follow_me` only edit faces in a root Group. Shared Group definitions are rejected to avoid silently changing all placements. Nested edit contexts are not supported in M2.
- Boolean operands must be distinct root-level manifold Groups or ComponentInstances. Inputs are duplicated, boolean work is done on copies, and the result is a newly identified object; source identities and source geometry remain untouched. `union`/`intersect` use official Group methods. `difference` calls `target_copy.split(tool_copy)` and selects the documented `self - other` result at index 1. `split` consumes its receiver and argument, returning `[other - self, self - other, intersection]`; the two unused result Groups are erased before commit. There is no fallback to the ambiguously described `trim` or `subtract` methods.
- `push_pull.distance_mm` is a world-visible length. Face push/pull distance is applied in its parent Group's geometry context, so M2.1 accepts only rigid parent transformations: translation and rotation. A matrix-based helper checks the three linear columns for unit scale, pairwise orthogonality, and right-handed orientation, and checks the affine matrix tail. Scale, shear, reflection, malformed, and non-finite transforms fail with `constraint_violation` before an operation starts.
- `follow_me` builds path edges inside the managed Group for the sweep. On success, edges with no attached faces are erased. Edges still connected to faces are retained as swept topology and reported in `warnings`; the API does not document that `Face#followme` consumes its edge arguments. Any failure aborts the full operation.
- Primitive tools remain low-level fallback capabilities. No future domain object types or `eval_ruby` are exposed.

## M2.1 API correctness findings

- The official [Group API](https://ruby.sketchup.com/Sketchup/Group.html#split-instance_method) defines `split` order as Difference2 (`other - self`), Difference1 (`self - other`), then intersection. Since the target copy is the receiver, result index 1 is exactly `target - tool`. The same documentation says the source Groups are replaced by the results, which is why the implementation uses copies and removes the two unused result Groups in the same operation.
- The [Group API](https://ruby.sketchup.com/Sketchup/Group.html#trim-instance_method) and its `trim` / `subtract` descriptions contain conflicting receiver/argument phrasing. M2.1 avoids those calls for difference.
- The [Face API](https://ruby.sketchup.com/Sketchup/Face.html#pushpull-instance_method) measures push/pull along the Face normal. HomeCAD cannot promise a world distance through arbitrary scaled or sheared parent contexts, so those transforms are explicitly unsupported for `push_pull`.
- The [Face API](https://ruby.sketchup.com/Sketchup/Face.html#followme-instance_method) specifies an array of path edges and a Boolean result, but does not promise that the input edges are consumed. HomeCAD therefore removes only edges that are demonstrably unreferenced after the sweep and keeps connected boundary edges with a warning.
- `Geom::Transformation#xaxis`, `#yaxis`, and `#zaxis` describe axis directions and are not sufficient to detect scaling. `Geometry.rigid_transform?` checks the linear 3×3 matrix columns returned by `to_a`, including scale, orthogonality, and determinant, plus the affine tail. See the official [Transformation API](https://ruby.sketchup.com/Geom/Transformation.html).

## Known manual checks

Standalone tests use SketchUp API doubles and do not substitute for the SketchUp kernel. In the real supported SketchUp version, run `scripts/smoke_m2.py` on a disposable model and verify boolean direction/source preservation, ordinary and scaled `push_pull`, Follow Me cleanup/warnings, screenshots, and exactly one native Undo per successful mutation. SketchUp-specific solid edge cases and topology sharing still require manual validation.
