# M3 Architecture contract

M3 provides typed generated architecture objects. Parameters and relationships are the source of truth. Architecture objects are regenerated by architecture tools; primitive mutation tools reject generated non-primitive HomeCAD objects.

## Capability and common behavior

Every M3 method requires `architecture.core.v1`. `hello` and `homecad_status` remain available to compatible older bridges even when the capability is absent. M3 does not change protocol version 1.

All public lengths and world coordinates are millimeters. Public angles are degrees. World points are `[x_mm, y_mm, z_mm]`. SketchUp internal inches remain private to the Ruby layer. Every mutation validates its proposed complete state before one `HomeCAD::Operation`; an exception aborts that operation. Mutations return the shared `status/operation/created/updated/deleted/warnings/revision` envelope. Per-object revisions start at 1 and increment once when effective geometry or domain state changes. The envelope revision is the primary result/target revision.

Domain attributes retain the base metadata fields `homecad_id`, `type`, `schema_version`, `revision`, and `generated`. Nested parameters and relationships are stored as canonical JSON strings in the `HomeCAD` AttributeDictionary and exposed as parsed `parameters` and `relationships` by the shared serializer. A hosted object's `wall_id` is also stored as a direct searchable metadata value.

## Wall and local frame

`create_wall` accepts `start_mm`, `end_mm`, `thickness_mm`, `height_mm`, and optional `name`. Walls are root-level managed Groups of type `architecture.wall`. The baseline is horizontal in plan within 1 mm. Wall length must exceed 10 mm; thickness and height must exceed 0.1 mm; all coordinates must be finite.

The frame origin is `start_mm`. U is the normalized XY vector from start to end. Z is global `[0,0,1]`. V is `Z × U`; therefore `U × V = Z`. The generated volume covers U `[0,length]`, V `[-thickness/2,+thickness/2]`, and Z `[0,height]`. `get_wall_frame` returns this frame and the wall dimensions. `local_to_world`/`world_to_local` use millimeters.

Wall updates preserve the root Group and HomeCAD UUID, replace its generated inner faces, and set its frame from the updated endpoints. All hosted objects keep their wall-local offsets. Window concept geometry and Room reference geometry are regenerated when their host boundary changes. An update that invalidates a cut or breaks a Room loop is rejected before opening an operation.

## Hosted cuts

`create_opening`, `create_door`, `create_window`, and `create_niche` create separate root-level semantic objects with their own UUIDs and a `wall_id` relationship. Their anchor is the lower-left corner of the cut in wall-local U/Z: `offset_mm` is U from wall start, `bottom_mm` is Z from the wall base, width proceeds +U, and height proceeds +Z. `depth_offset_mm` is a signed V distance from the centerline. `side` is exactly `center`, `positive_v`, or `negative_v`; M3 does not infer room-inside/outside.

Opening, Door, and Window cuts pass through the full wall thickness. Door bottom is fixed at 0. Window has a simple generated glass panel with a perimeter frame. Niche removes material only from its selected `positive_v` or `negative_v` side and requires `0 < depth_mm < wall.thickness_mm`.

Wall shell geometry is deterministically regenerated from the wall dimensions and all hosted cuts by partitioning U/V/Z at cut boundaries and emitting only solid/empty boundary faces. It does not use SketchUp Solid Tools. M3 allows up to 16 hosted cuts and 4 niches per wall. Any U/Z overlap between hosted cut rectangles, including a niche and through cut, is rejected. Wall shortening/height reduction that invalidates a hosted object is rejected; attachments are never clamped.

## Column and updates/deletion

`create_column` creates an independent rectangular vertical `architecture.column` Group with world origin, width/depth/height in mm, and `rotation_degrees` about global Z. Polygonal columns are outside M3.

`update_architecture_object(target, changes)` resolves one HomeCAD object through the shared Targeting resolver and permits only type-specific editable parameters. Identity, type, and schema version are immutable. `delete_architecture_object` tombstones are serialized before erase. Deleting a hosted object rebuilds its host wall in the same operation. A wall with hosted objects or dependent Rooms requires `cascade=true`; cascade removes all those semantic objects and the wall in one Undo operation.

## Rooms

`create_room` takes an explicitly ordered array of distinct HomeCAD wall IDs. The directed endpoints must form one closed, simple, nonzero-area XY loop within a 1 mm endpoint tolerance; walls must lie at one floor elevation. The array order is preserved. Room-facing side is derived from polygon winding and each boundary wall's U direction (`positive_v` or `negative_v`) and stored with the Room. An optional generated floor face is reference geometry; its area is approximate and does not represent finished-floor/net area.

`detect_rooms` is read-only. It snaps wall baseline endpoints within 1 mm, reports only simple closed components where each snapped endpoint has degree 2, and reports warnings for open, crossing, T-junction, or ambiguous topology. It never creates Room metadata or chooses wall order for `create_room`.

SketchUp's model remains the project root; M3 creates no Apartment container Group.

## Tools and annotations

Read-only: `get_wall_frame`, `detect_rooms`.

Non-idempotent creation: `create_wall`, `create_opening`, `create_door`, `create_window`, `create_niche`, `create_column`, `create_room`.

Destructive, non-idempotent mutations: `update_architecture_object`, `delete_architecture_object`. MCP annotations are client-facing hints, not enforcement.

## Verification boundary

Ruby and fixture tests cover frame math, validation, wall boundary decomposition, references, revisions, identity, and tool forwarding. Real SketchUp checks are still required for wall shell manifoldness, multiple cuts, niche depth, window concept geometry, wall transformations, hosted regeneration, Room faces, and one-step Undo of multi-object regeneration. Run `scripts/smoke_m3.py --confirm-disposable` only with an opened disposable/test model.
