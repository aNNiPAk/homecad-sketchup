# M5.3 project defaults and Furniture presets

`project.defaults.v1` exposes `get_project_settings` and `update_project_settings`.
Settings are stored on the SketchUp Model as HomeCAD metadata, with revision 0 before the first
write. Editable fields are `panel_thickness_mm` (>0), `back_thickness_mm` (>=0),
`cabinet_wall_clearance_mm` (>=0), `material_id`, and `front_material_id` (null or a nonempty
identifier). All lengths are millimeters. These values are project choices, not building codes.
M5.2 service clearances remain explicit per Kitchen module.

`furniture.presets.v1` exposes `list_furniture_presets`, `get_furniture_preset(preset_id)` and
`create_cabinet_from_preset(preset_id,overrides)`. The initial HomeCAD-authored catalog contains
`base_open.v1`, `base_shelves.v1`, `wall_open.v1`, and `tall_shelves.v1`.
Precedence is explicit overrides, then fixed preset fields, then project settings, then
built-in Furniture defaults. Preset-created Cabinet roots store `furniture_source_json` with
the preset ID/version, explicit overrides, and inherited field names. The effective
`furniture_params_json` is a derived current value. A direct `create_cabinet` and all legacy
Cabinets without source metadata remain pinned and unaffected by project updates.

Updating project settings preflights every Cabinet that inherits a changed field. A failure
starts no SketchUp operation and changes no Cabinet or project revision. A successful change
is one `HomeCAD::Operation`, increments the project revision once, and increments each Cabinet
whose effective semantic state changed once. A direct Cabinet update of an inherited field
turns that field into an explicit override, even when its value equals the inherited value.
Read-only tools never write metadata. Protocol version remains 1.
