# Эксперимент: компактное описание моделей фурнитуры

Дата: 27 сентября 2026 года. Это исследовательский прототип; формат не подключён к HomeCAD.

## Короткий вывод

Повторное использование геометрических деталей даёт сильное сжатие для изученных серий Blum. Для 50 файлов Antaro и MERIVOBOX (56,87 МБ) общий архив HCG1 занял 356,8 КБ, или 0,63% размера исходных `.skp`. **Это сравнение только геометрии:** HCG1 пока не сохраняет материалы, текстуры, атрибуты Dynamic Components и редактируемую структуру SketchUp. Его можно рассматривать как прототип компактного визуального представления, а не как готовую замену исходным моделям.

Динамические словари этих же 50 файлов разобраны отдельно в [отчёте по данным Blum](BLUM_DYNAMIC_DATA_ANALYSIS.md): повторяющиеся наборы значений тоже хорошо сжимаются, но это пока не добавляет HCG1 поведение Dynamic Components.

## Образцы и способ

Прочитаны 25 файлов [Blum Antaro](<../References/PLUGINS/DC_Change_Mat/Components/Выдвижные ящики/>) и 25 файлов Blum MERIVOBOX из того же каталога. Исходные модели не менялись. [Исследовательский конвертер](../scripts/research/hardware_codec.py) использует установленную библиотеку SketchUp C API для чтения граней, отдельных рёбер, групп, экземпляров компонентов и их преобразований. Геометрию граней он получает через [`SUMeshHelper`](https://extensions.sketchup.com/developers/sketchup_c_api/sketchup/struct_s_u_mesh_helper_ref.html), а вложенность — через [`SUEntities`](https://extensions.sketchup.com/developers/sketchup_c_api/sketchup/struct_s_u_entities_ref.html).

Файл HCG1 состоит из сигнатуры `HCG1`, длины распакованного JSON и сжатого zlib JSON. В JSON корневые модели ссылаются на определения по SHA-256 содержимого. Каждое определение содержит:

| Поле | Содержимое |
| --- | --- |
| `v` | Общие вершины в целых сотых долях миллиметра. |
| `t` | Индексы треугольников. |
| `l` | Индексы отдельных рёбер, не принадлежащих граням. |
| `c` | Ссылки на дочерние определения и матрицы размещения. |

Линейные коэффициенты матрицы округлены до `10⁻⁶`, перенос — до 0,01 мм. Одинаковые определения хранятся один раз для всех моделей архива. Отдельный режим распаковывает HCG1 в читаемый JSON и собирает один корень в OBJ для проверки геометрии.

## Измерения

Размеры указаны в десятичных МБ (1 МБ = 1 000 000 байт). `zlib(.skp)` — независимое сжатие каждого исходного файла без потери его содержимого; его нужно распаковать для использования как `.skp`. `HCG1 отдельно` — сумма архивов, если не разделять определения между моделями.

| Набор | `.skp` | `zlib(.skp)` | HCG1 отдельно | HCG1 общий | Доля от `.skp` |
| --- | ---: | ---: | ---: | ---: | ---: |
| MERIVOBOX, 25 файлов | 34,946 МБ | 14,473 МБ | 1,456 МБ | 0,231 МБ | 0,66% |
| Antaro, 25 файлов | 21,926 МБ | 8,875 МБ | 0,673 МБ | 0,119 МБ | 0,54% |
| Обе серии, 50 файлов | 56,872 МБ | 23,348 МБ | 2,129 МБ | 0,357 МБ | 0,63% |

В общем наборе извлечены 102 771 грань, 324 336 треугольников и 3 884 отдельных ребра; обнаружены 2 916 экземпляров компонентов и 172 группы. Получилось 354 уникальных определения, из которых 208 встречаются более чем в одной модели. Общий HCG1 меньше суммы отдельных HCG1 примерно в шесть раз: здесь повторное использование деталей важнее самого zlib.

Чтение 50 исходных файлов через C API заняло 8,824 с, кодирование 0,178 с, декодирование 0,039 с на этой машине. Полная проверка восстановленных границ заняла 2,438 с. Это единичный локальный замер, а не тест производительности SketchUp при вставке компонентов.

## Проверка и пределы точности

После кодирования архив декодирован обратно в те же целочисленные вершины, индексы и связи. Для каждого из 50 образцов вычислены границы развёрнутой иерархии и сравнены с `SUEntitiesGetBoundingBox` исходного файла. Максимальное расхождение координаты границы составило 0,00354 мм. Максимальное округление отдельной координаты при переводе в сетку — 0,005 мм. Один образец, `Blum MERIVOBOX M.skp`, дополнительно развёрнут из HCG1 в OBJ: 6 634 вершины, 12 716 треугольников и 140 линий; границы OBJ совпали с границами декодированной модели.

Это подтверждает корректность кодирования *извлечённой геометрии* в рамках выбранной точности. Повторный импорт OBJ/HCG1 в SketchUp и визуальное сравнение материалов не проводились. Округление может менять топологию очень мелких элементов, даже когда общий габарит совпадает.

## Что формат пока теряет

- Материалы, текстуры, UV-развёртку, цвета и прозрачность. В исходных 50 файлах C API насчитал суммарно 452 записи материалов по файлам, из них 141 с текстурами; повторяющиеся материалы включены в этот счёт.
- Атрибуты и формулы Dynamic Components, поведение `onclick`, имена деталей, артикулы, слои, видимость, свойства рёбер и исходные границы граней. Исходные многоугольники превращены в треугольники.
- Неиспользуемые определения, служебные данные SketchUp и возможность открыть файл как редактируемый `.skp`.

Поэтому разница 56,87 МБ → 0,357 МБ **не означает** сжатие полного SKP в 160 раз без потерь. Полный побайтовый вариант `zlib(.skp)` дал 23,348 МБ. Для решения о внедрении нужен следующий опыт с материалами/UV, необходимыми атрибутами и обратной сборкой в SketchUp. Он покажет реальный размер и стоимость поддержки формата.

## Воспроизведение

Конвертер требует Python и путь к установленной `SketchUpAPI.dll`. Результаты следует сохранять вне отслеживаемых файлов репозитория; в этом опыте использована игнорируемая папка `.references/hardware-benchmark/`.

```powershell
$files = Get-ChildItem 'References/PLUGINS/DC_Change_Mat/Components/Выдвижные ящики' -Filter 'Blum MERIVOBOX*.skp' -File | Select-Object -ExpandProperty FullName
& $python scripts/research/hardware_codec.py --dll $sketchupApiDll --output .references/hardware-benchmark/merivobox.hcg --report .references/hardware-benchmark/merivobox.json $files
& $python scripts/research/hardware_codec.py --unpack .references/hardware-benchmark/merivobox.hcg --output .references/hardware-benchmark/merivobox-decoded.json --obj .references/hardware-benchmark/merivobox.obj --root-name 'Blum MERIVOBOX M.skp'
```

`$python` и `$sketchupApiDll` здесь означают локальные абсолютные пути к исполняемому Python и библиотеке SketchUp C API. Архивы, OBJ и JSON из опыта содержат производную геометрию сторонних моделей и не должны попадать в коммиты без выяснения прав. Исходные `.skp` и `References/` остались без изменений.
