# M6.1 Electrical System Completion (0.14.0, protocol 1)

Adds capabilities electrical.panels.v1, electrical.consumers.v1,
electrical.routes.v1, electrical.load.v1 and electrical.rules.v1. M6.0 point/circuit
calls retain their schemas and behavior. New Circuit fields/route detach and explicit
rules requests require the corresponding capability. No new fields are injected
into old Circuits just by reading or performing a normalized old-style no-op.

## Panel
Tools create/get/update/delete_distribution_panel and assign_circuit_to_panel.
Panel is electrical.panel, generated root Group, UUID/revision with the existing
Electrical dimensions and center-based Wall/world placement contract. It follows
Wall movement and is protected from primitive editing. Circuit.parameters.panel_id
owns assignment; get_distribution_panel derives circuit_ids. assign accepts null
to detach. Circuit may explicitly request require_panel=true, which is a validation
condition, not an automatic placement rule. Panel deletion rejects assigned Circuits
unless detach_circuits=true; Circuits remain and panel_id becomes null. Panel revision
tracks its own state/placement and circuit membership; Circuit revision also tracks assignment changes. Wall
cascade clears panel references in the same outer operation.

## Consumer and load
Tools create/get/list/update/delete_consumer, connect_consumer,
find_unpowered_consumers and get_circuit_load. Consumer is a model JSON record with
ordinary UUID/schema_version/revision, generated=false, no copy of source geometry.
Parameters: name, source_object_id, connection=outlet|direct (default outlet), optional
rated_power_w>=0, voltage_v>0, point_id, description. Unknown ratings/point are null.
M6.1 supports one Consumer per existing semantic kitchen.appliance UUID. Logical
targets use exact UUID through Targeting. Identity/type/schema are not editable.

outlet requires electrical.outlet; direct requires connection_point or junction_box.
connect_consumer(point_id=null) disconnects. Incompatible connection is rejected before
mutation; validation can still diagnose manually corrupted/later invalid references.
Consumer stores no circuit_id. get_consumer derives it only through its point.
Unpowered status distinguishes missing_point, point_missing, point_not_on_circuit,
incompatible_connection, and circuit_missing. List/find responses are paginated with
limit 1..100 (default 50), offset>=0 and total/has_more.

DomainHooks cascades Consumer deletion when an appliance UUID disappears or its type
changes from kitchen.appliance, inside the same operation. Source regeneration keeping
UUID/type keeps Consumer, including ratings. Kitchen has no Electrical dependency.
Explicit Point deletion may leave point_id as a diagnostic reference; find_unpowered
reports point_missing. Source references are never silently switched to another object.

Load fields: consumer_ids, known_consumer_count, unknown_power_count, rated_power_w,
voltage_v, estimated_current_a, warnings. Sum only known explicit powers; unknown
power does not become a guessed appliance rating. Current is informational known
power/explicit Circuit voltage. If voltage is absent/mismatched, or a nonempty set
has no known power, current is null. Partial sums/unknown voltage generate warnings.
Mismatch tolerance is 0.01 V. No phase, diversity, power-factor or protection sizing.

Consumer creation/update/connect/delete on a Circuit increments affected old/new
Circuit revision once. Point transfer A->B uses existing point membership revisions;
Consumer revision remains unchanged while derived load moves. No-op changes have no
Undo/revision. Cross-domain deletion aggregates changes to avoid double Circuit bumps.

## CableRoute
Tools create/get/list/update/delete_cable_route. Root electrical.cable_route Group
contains concept polyline; no diameter/precise collision claim. Params: name,
circuit_id (exact UUID or explicit null), path_mm (2..128 finite world points), optional
description. Adjacent points must differ by more than 0.01 mm; total length must be
finite. Derived length_mm is the sum of segments. UUID/root identity is preserved on
update. Full path is serialized without the general entity-array truncation.

Routes own Circuit references; changing a route increments old/new circuit graph
revisions once. World paths do not auto-follow moved points/Walls and have no endpoint
bindings. Circuit deletion with routes rejects unless detach_routes=true, separate
from detach_points. Detach keeps polyline, clears circuit_id, increments route revision,
and generic validation reports invalid_route_circuit until it is assigned again.

## Generic rules and acceptance
validate_electrical additively accepts ruleset='generic' and constraints={require_panel:
true|false}. Other rulesets return unsupported_operation. Existing findings/total/
limit/offset/has_more remain. Adds consumer_unpowered (with status), voltage_mismatch,
orphan_reference, missing_panel, invalid_route_circuit. Findings contain affected
Consumer/Circuit/Panel/Route/Point UUIDs and warning severity. National numeric rules
are not supplied. Geometry findings remain HomeCAD-only advisory checks.

Every mutation uses one native HomeCAD operation with abort on exception. Tombstones
precede deletion, and graph repairs run before commit. All new read tools have read-only
MCP hints. Generated root and child geometry remains guarded. RBZ explicitly includes
the five new Electrical modules. Acceptance runs existing M6 smoke plus the additional
system flow via dev_verify --milestone m6 --fast and --packaged on the owned fixture.
The system screenshot requires a non-flat native image and camera restoration;
capture metadata additively includes camera_capture and ImageRep-backed
image_has_variation (null when ImageRep is unavailable). This is pixel diagnostics,
not a substitute for reviewing scene geometry. Native export disables antialias to
avoid background-only GPU exports observed in the acceptance fixture.
M7 Lighting, automatic cable/protection selection and normative rules remain out of scope.

## M6.1.1 hardening

Panel circuit membership changes preflight both old/new Panel locks and increment
Panel revision once per affected Panel, in the Circuit's single Undo operation.
No-op assignment does not open an operation. Deleted Panels use tombstones.
Panel collision findings use full 3D OBB SAT against shared HomeCAD volumes and
Electrical points/Panels; self and nonpenetrating contact are excluded. Kitchen
service-zone obstacle selection retains its existing contract.
Consumer source cascade is limited to affected semantic Kitchen UUIDs, including
children of deleted Kitchen roots. Unrelated pre-existing orphans remain diagnostic.
get_circuit returns derived consumer_ids, route_ids, panel_id and existing member_ids.
find_unpowered_consumers includes name, source_type (null if missing), point_id,
derived circuit_id and reason/status. get_electrical_ruleset(ruleset="generic") is
read-only under electrical.rules.v1; other rulesets return unsupported_operation.
Version remains 0.14.0 for this pre-merge hardening; no release tag is created.
