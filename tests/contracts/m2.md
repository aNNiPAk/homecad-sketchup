# M2 Primitive Geometry Contract

M2 exposes low-level geometry tools for developer/fallback use. It does not replace future Architecture, Furniture, Kitchen, Electrical, or Lighting tools.

## Units and coordinates

- Lengths and coordinates are millimeters; angles are degrees.
- Points are `[x_mm, y_mm, z_mm]` in world coordinates.
- SketchUp internal inches never cross the MCP boundary.
- Circle and polygon radius means radius to the circumference/vertices. `create_polygon` makes a regular polygon.
- Arc angle values are absolute degrees in the plane described by `normal` and `x_axis`; the sweep must be nonzero and no larger than 360 degrees.
- Circle, arc, and polygon segmentation is bounded to 512 segments/sides.

## Tools

`create_group`, `create_face`, `create_edge`, `create_box`, `create_circle`, `create_arc`, and `create_polygon` create a root Group containing the geometry. No primitive creation leaves loose entities in the model root. Face creation delegates coplanarity and topology acceptance to SketchUp; arbitrary self-intersecting polygons are not promised.

`push_pull` and `follow_me` target one Face inside a root Group. The entity must resolve uniquely, be valid and unlocked, and the Group definition must not be shared by multiple instances. `push_pull.distance_mm` is a world-visible distance. The parent Group transform must be rigid: translation/rotation only, with no scale, shear, or reflection. The tool rejects non-rigid transforms before starting an operation. `follow_me` accepts 2–512 world-coordinate path points and does not repair invalid paths; adjacent points closer than 0.01 mm are rejected.

Follow Me creates temporary path edges in the same Group as the profile Face. After a successful sweep, unreferenced path edges are erased. If a path edge has faces attached and therefore forms part of the swept topology, it remains and the mutation response includes a warning. A failed sweep aborts all path and generated geometry changes.

`transform_object` accepts a root Group or ComponentInstance and one transform:

- `{"type":"translate","vector_mm":[x,y,z]}`
- `{"type":"rotate","axis_point_mm":[x,y,z],"axis_vector":[x,y,z],"angle_degrees":n}`
- `{"type":"scale","origin_mm":[x,y,z],"factors":[sx,sy,sz]}`

Scale factors must be positive. Primitive transforms reject generated non-primitive HomeCAD objects.

`boolean_operation` accepts `union`, `difference`, and `intersect` on distinct, root-level manifold Groups/ComponentInstances. It duplicates both inputs, operates on the duplicates, and returns a new HomeCAD result Group; the original inputs are preserved. `difference` means exactly `target - tool`. The implementation calls `tool_copy.subtract(target_copy)`, following the official parameter description that the argument is the solid to subtract the receiver from. The API summary prose conflicts with that description. The previously installed build used `split(...)[1]`; a real asymmetric smoke on SketchUp 26.2 showed that result had tool-minus-target bounds, contrary to the documented index mapping. Therefore HomeCAD no longer selects a `split` result by index. The new `subtract` invocation still needs a real SketchUp smoke after installing the updated RBZ. If `subtract` is unavailable or fails, the request returns `unsupported_operation` or `geometry_error` and aborts. The original source objects remain unchanged; copies are removed inside the same operation.

## Mutation contract

Every MCP mutation validates inputs and resolves targets before opening exactly one `HomeCAD::Operation`. Changes and metadata writes happen inside that operation. Any exception aborts the operation. A successful response uses:

```json
{"status":"success","operation":"create_box","created":[],"updated":[],"deleted":[],"warnings":[],"revision":1}
```

Created HomeCAD objects receive an RFC 4122 UUID and metadata in the `HomeCAD` AttributeDictionary:

```json
{"homecad_id":"uuid","type":"primitive.box","schema_version":1,"revision":1,"generated":true}
```

Each subsequent HomeCAD mutation increments the mutated object's revision. A boolean result begins at revision 1. Primitive tools do not mutate parameters of future domain objects; generated non-primitive targets are rejected.

All M2 methods require `geometry.primitive.v1`. MCP annotations classify create calls as non-read-only, non-idempotent creation. Existing-object mutations are non-read-only, destructive, and non-idempotent. These annotations are hints, not enforcement.

## Smoke test

Only use `scripts/smoke_m2.py --confirm-disposable` on a disposable/test model. It verifies box transform/Undo, asymmetric `target - tool` boolean difference/source preservation, ordinary push/pull, scaled push/pull rejection, and an L-shaped Follow Me operation. It captures screenshots and undoes each successful mutation. It checks that created IDs are gone and reports a cleanup failure explicitly; initial/final model modified state is also compared.
